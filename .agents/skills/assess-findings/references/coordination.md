# Coordinate Related Work

Read this when assigning assessment, research or implementation work, transferring ownership, or receiving evidence that changes another assignment.

Use one coordinator for the active task across co-active skills. It retains scope, phase permissions, task ownership, shared-record writes and final synthesis. Roles are responsibilities, not a required agent count. Work directly when context is tightly coupled or a handoff adds little value; delegate bounded independent work when its benefit justifies the context and integration cost. Reuse an owner for related follow-ups. Available host capacity is a ceiling, not a staffing target.

Each assignment states:

- The question or observable outcome, boundaries and completion or stopping condition.
- Relevant records, accepted decisions, evidence paths and version/provenance, including what remains unknown.
- Source/history permissions and allowed actions; writable paths, shared resources and cleanup ownership.
- Required return: findings or changes, inspectable evidence, limits, last completed action and next step. For tracker reconciliation, return the [related-work account](tracker-decisions.md#return-the-decision-basis), including discussion coverage and the basis for the contribution route.

Pass the relevant context and pointers, not the entire archive. Workers request missing context or further investigation through the coordinator rather than spawning overlapping teams. Keep implementation, assessment, tracker reconciliation, code review and runtime verification distinct even when one executor performs several roles. Worker agreement is not evidence.

The coordinator accepts returned evidence, reconciles the authoritative record and sends material changes to affected owners. State what changed, its evidence and which assumptions or checks are invalidated. Pause an action whose correctness depends on an invalidated assumption; unaffected work continues. Owners recheck the current agreement before the next dependent action and identify the state their results examined. A new worker inherits prior source/history exposure; it does not restore independent audit provenance.

Serialize conflicting writes or shared environments. If repeated shared interpretation makes assignments inseparable, consolidate them under an existing suitable owner instead of sending repeated partial context. Transfer the last completed action, evidence, current state, pending work and live resources; confirm the old executor stopped affected actions before the new owner uses them. On pause, stop dispatch and affected workers, preserve the checkpoint and account for resources. Retiring an agent does not stop its processes. Cleanup and resource transfer remain explicit.

If delegation is unavailable, use the same bounded method inline or retain a queued assignment with its reason and resumption condition. Report only work actually performed; inline checking is not independent verification.

## Independent assessment inputs

Use this branch when the consuming assessment calls for an independently formed judgment. The coordinator prepares the inputs and remains responsible for scope and shared records; one assessor owns the judgment. Check the host's actual history-inheritance setting and start the assessor without the discoverer's conversation. If isolation is unavailable or the assessor already knows that reasoning, report the exposure and use a qualified assessment rather than claiming a fresh judgment. This does not reopen source or history gates or reset the audit's discovery provenance.

Give the assessor the question, scenario, revision, observations, confirmed requirements and constraints, inspectable evidence, counterevidence, unknowns and permitted checks. Keep the discoverer's classification, diagnosis and preferred remedy separate until the assessor records an initial judgment or identifies the evidence preventing one. Before dispatch, check both the prompt and its assigned read paths. For records that mix evidence with the discoverer's conclusions, supply source-located excerpts and retain full-record access with the coordinator for targeted requests; a link to read the whole record can expose the withheld judgment. Clean evidence sources can be read directly. Route missing-context requests through the coordinator before widening access. Later compare the discoverer's explanation with the evidence and address material disagreements.

When requirements exist only in chat, retain the smallest original excerpts that establish each relevant choice, its conditions and later revisions. A short confirmation applies to the specific proposal it answers; agreement to try a remedy does not establish its diagnosis. For example, "Keep empty rows in the export; skip scheduled exports" establishes behavior and scope even if the same message blames a serializer. Preserve those constraints, keep the diagnosis provisional, and leave ambiguous choices unresolved rather than completing them from the discoverer's interpretation. Include necessary adjacent messages when a reply cannot stand alone.

At entry, make one bounded coverage check for important requirements, revisions and contrary results. Compare the supplied claims with their cited sources and available task-context range; a selected excerpt list alone cannot establish completeness. Follow concrete gaps with targeted source requests under the existing access permissions. A third worker is optional when a named omission concern warrants checking original material; it returns missing or misrepresented evidence and its source, not a second full assessment. Reuse existing records and investigation methods without requiring a transcript index or fixed form. Inaccessible originals leave a named coverage limit.

When decisive evidence cannot be separated from the discoverer's reasoning without changing its meaning, read the necessary mixed material, retain any initial judgment and report the exposure. Explain changes through new evidence or corrected reasoning; do not restart merely to restore an isolation claim. Follow-up evidence normally returns to the same assessor under the consuming skill's continuity rules.
