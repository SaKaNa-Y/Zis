# Verify a Documentation Repair

Use the edited document itself as the source of execution inputs. Copy or extract its commands and configuration, substitute explicit placeholders, and record any setup changes needed by the test environment.

For example, an installation guide can add an override that conflicts with an existing direct dependency. Start with that dependency present. Run the old instructions to establish the conflict, then run the corrected example taken from the document. Use a relevant control to check the claimed scope.

Distinguish environment setup from corrections to the instructions. If a manual adjustment supplies the missing fix, the run does not verify the document as written. Report the adjustment and repair the document before repeating the affected check.

Choose checks that can change the conclusion. A wording-only edit needs proportionate review, not an installation exercise.
