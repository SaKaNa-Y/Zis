# Trace a capability change

Use this route when the question concerns an old effect, a removal, or a replacement. Keep the product, operating mode, desired effect, and versions fixed from the conversation. Interpret later shorthand within those conditions. Change them when the user changes the requirement or evidence corrects a premise.

1. Start from the strongest existing evidence and its source pointers. Read the original change and its reason when they bear on the question. Inspect the parent revision and relevant discussion to resolve gaps in the change description.
2. Trace the old input through its consumers to the claimed effect. A declared option or a file writer alone does not establish that effect. Distinguish intended behavior from behavior the implementation actually provided.
3. Follow any migration or replacement named in the change. Inspect the current command registration, public options, or API entry point for the same product and mode. Test a replacement against the same effect, including concrete alias or relocation leads.
4. Return the old effect, what changed, and the supported current route. If no equivalent exists, bound that result to the inspected product, mode, and version. Support it with the relevant entry points and resolved leads. If a decisive source is unavailable, name the remaining gap.

These checks can establish a renamed input, a moved capability, a removed capability, or an input that never produced the claimed effect. Use the evidence to choose the result. A failed text search alone leaves the replacement question open.

Before another lookup or experiment, identify which gap in this chain it will settle. Reuse completed checks that still apply. A working procedure in another product or mode establishes an alternative, not a native replacement. Resolve the native question first. Offer an alternative when it serves the user's requested outcome, with the changed conditions explicit.

Stop when the old effect and current relevant entry points are accounted for and concrete contrary leads are resolved. Return to the consuming task. This route supplies evidence for that task's decision about documentation, migration, or repair.
