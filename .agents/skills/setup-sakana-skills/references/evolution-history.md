# Configure Evolution History

Use when configuring Evolve Skills. Setup owns the configuration; Evolve owns [retrieval and maintenance](../../evolve-skills/references/history-reuse.md). Setup can configure an existing installation without running that workflow.

Inspect the selected client's effective user and project instructions. Reuse an existing evolution-specific setting, whether inline or reached through a pointer. Ordinary Working Records roots and commit authority remain separate.

Resolve these values from current instructions, applicable project overrides, then global defaults:

- Verified skills source repository and the persistent detailed-history root.
- Archive ownership and publication policy, navigation entrypoint, and known installation identity.
- Save authority and any separately selected publication or backup behavior.
- Access from the selected clients and from a different working project.

A central root stays central when the working directory changes. Project identity belongs in evidence provenance. A generic project record setting is not an evolution-history override. An unavailable archive is an access limit, not a reason to create another history in the project.

Show the exact existing entrypoint, proposed text and effective values before writing personal settings. Reuse inline guidance when already established; an external guidance document is optional. A concise entrypoint can state:

```text
When using Evolve Skills, use <central history root> for detailed evolution
history, including when the working project is elsewhere. Read <archive policy>
and <history README>. Record the project's identity as evidence provenance.
Keep Working Records locations and commit authority separate. If this archive
is unavailable, report the limit and retain pending updates without creating
a substitute archive in the working project.
```

Replace placeholders with verified values in the reviewed configuration. The shared skill itself carries no personal machine path. Configuration support is not approval to edit a user's global settings. Preserve existing save authority and private/public boundaries; an ignored archive is not backed up by ordinary pushes.

After applying selected settings, read the configuration from each selected client entrypoint and verify resolution from another working directory. A second setup pass must reuse sufficient guidance without duplicating it. Report access and installation limits. Skill installation, historical screening, migration, commits and publication remain separate operations.
